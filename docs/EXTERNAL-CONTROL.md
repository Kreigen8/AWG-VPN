# Внешнее управление AWG VPN

Доступно с `0.2.4-preview`. Другие приложения на этом же Android-устройстве могут запросить подключение и отключение уже сохранённых профилей. Сетевого сервера управления, импорта конфигов и выдачи ключей через этот интерфейс нет.

## Включение

1. В AWG VPN подключитесь обычной кнопкой хотя бы один раз и подтвердите системное разрешение VPN.
2. Прокрутите главный экран до «Внешнее управление» и включите «Разрешить управление через внешние приложения». По умолчанию галочка выключена, включая обновление со старой версии.
3. Приложение-отправитель должно объявить `ru.routevpn.app.permission.CONTROL_TUNNELS` в своём AndroidManifest.xml и запросить это разрешение у пользователя через Android. Одна галочка в AWG VPN не даёт разрешения произвольным приложениям.

Приложение, которому вы выдали разрешение, сможет отключать VPN. Снятие галочки запрещает новые команды и отменяет ещё не принятые команды старого поколения; уже выполняющаяся операция может завершиться. Сам VPN при снятии галочки не отключается. Разрешение также можно отозвать у приложения-отправителя средствами Android.

Generic-приложение автоматизации не обязательно умеет объявлять произвольное новое разрешение. Нужна явная поддержка AWG VPN или собственный интегратор с декларацией ниже. Команда `pm grant` не добавляет отсутствующее разрешение в manifest стороннего приложения.

## Протокол

Пакет: `ru.routevpn.app`. Команды отправляются явным broadcast в компонент `ru.routevpn.app/.ExternalControlReceiver` или с `setPackage("ru.routevpn.app")`.

| Action | Действие |
| --- | --- |
| `ru.routevpn.app.action.SET_TUNNEL_UP` | Подключить сохранённый профиль. Другой работающий профиль переключается последовательно в той же VPN-службе. Повторный UP текущего профиля не пересоздаёт туннель. |
| `ru.routevpn.app.action.SET_TUNNEL_DOWN` | Отключить VPN. Запрос восстановления очищается, поэтому watchdog и обычный автозапуск не отменяют намеренное отключение. |

Необязательные строковые extras:

- `tunnel`: точное имя сохранённого профиля, максимум 80 символов. Если имена повторяются, команда отклоняется.
- `profile_id`: внутренний ID существующего профиля, максимум 128 символов. Этот selector удобен интегратору, которому ID уже известен.

Передавайте только один selector. Без selector UP использует выбранный в приложении профиль, а DOWN отключает текущий. DOWN с selector не отключает другой работающий профиль. Несуществующие/неоднозначные имена, неверные типы extras, пустые и слишком длинные значения отклоняются. Содержимое `config` и любые лишние extras не передаются VPN-службе. Список профилей, их имена, ID и конфиги через API не возвращаются.

Для ordered broadcast результат содержит только фиксированный код и текст:

| Код | Текст | Значение |
| --- | --- | --- |
| -1 | `ACCEPTED` | Команда передана внутренней службе. Это не подтверждение handshake или исправности интернета. |
| 1 | `DISABLED` | Галочка выключена или команда устарела после её изменения. |
| 2 | `BAD_REQUEST` | Неверная команда или selector. |
| 3 | `PROFILE_NOT_FOUND` | Нужного сохранённого профиля нет. |
| 4 | `AMBIGUOUS_PROFILE` | По имени найдено несколько профилей. |
| 5 | `VPN_PERMISSION_REQUIRED` | Нужно открыть AWG VPN и подтвердить системный запрос VPN. |
| 6 | `BUSY` | Завершается отключение или переполнена очередь команд. |
| 7 | `UNAVAILABLE` | Android запретил запуск в фоне либо хранилище временно недоступно. |

Без разрешения Android не доставляет broadcast этому receiver. Результат от AWG VPN в этом случае также не приходит. Обычный unordered broadcast не возвращает результат.

Android сохраняет ограничения фонового запуска служб. Интерфейс не открывает экран и не запрашивает VPN-разрешение автоматически в обход этих ограничений. В частности, сценарий должен учитывать отсутствие VPN-разрешения и ограничения фонового запуска Android 12+.

## Пример интеграции

Manifest приложения-отправителя (AWG VPN должен быть установлен до установки интегратора):

```xml
<uses-permission android:name="ru.routevpn.app.permission.CONTROL_TUNNELS" />
```

После пользовательского предоставления этого runtime-разрешения:

```kotlin
val request = Intent("ru.routevpn.app.action.SET_TUNNEL_UP")
    .setClassName("ru.routevpn.app", "ru.routevpn.app.ExternalControlReceiver")
    .putExtra("tunnel", "Мой VPN")
context.sendBroadcast(request)
```

Для отключения используйте action `ru.routevpn.app.action.SET_TUNNEL_DOWN`. Имена пакета и actions AmneziaWG/WireGuard отличаются; они не являются aliases нового интерфейса.

## Диагностика и совместимость

Во внутренней диагностике соединения источники отмечаются отдельно: `external_connect`, `external_disconnect`, `manual_disconnect`, `watchdog_reconnect`, изменения сети и системное отключение. Имена отправителей и содержимое профилей в события не записываются. Работа watchdog не зависит от новой галочки.

Служебный extra старого launcher-пути `tile_connect` больше не запускает VPN. Плитка в шторке продолжает напрямую управлять приватной службой после разблокировки. Если требуется разрешение или Android запретил прямой запуск, плитка открывает главный экран, где пользователь нажимает кнопку подключения.

При обновлении сохраняются пакет `ru.routevpn.app`, сертификат подписи, файл профилей, AES-ключ Android Keystore, схема шифрования и namespaces настроек. Внешнее управление добавляет только два необязательных поля в существующие настройки подключения. Принятая команда смены профиля меняет текущий выбранный профиль, сохраняя конфиги и списки приложений всех профилей.

Проверки включают metadata manifest/permission, политику команд, валидацию selectors, отмену после изменения настройки, приватность intents, реальные lifecycle/worker-переходы с явным fake backend, сохранение зашифрованного старого профиля и native-графику чекбокса. Это не замена проверке разрешений между двумя реальными приложениями на конкретной прошивке Android.
